# Event-Time Ordering and Late Arrival

This fixed synthetic demonstration compares a category decision based on event
time with the same decision based on arrival order. It also shows the limit of
event-time reconciliation when the latest logical event has not arrived.

## Run and Verify

From the repository root with JDK 17 and Python 3.9+:

```bash
./gradlew :benchmarks:runEventTimeScenario --no-daemon
python3 tools/verify_event_time_results.py benchmarks/build/results/event-time-ordering/results.jsonl
```

Use `--args='--output /path/to/results.jsonl'` to select another output path, or
`--args='--help'` for runner arguments. Source archives can supply
`--source-commit FULL_SHA`; evidence records that identity as caller-supplied.
Git checkouts record their actual SHA and dirty status.

## Controlled Timeline

All times below are seconds after `2026-01-01T00:00:00Z`. The decision occurs
at second 40, inclusively. Event a occurs at second 10 and sets `travel`;
event b occurs at second 20 and sets `technology`. Ground truth for this one
synthetic key is the latest event generated by the decision boundary: b.

| Case | a arrives | b arrives | Selection policy | Outcome | Evaluation | Canonical class |
| --- | --- | --- | --- | --- | --- | --- |
| `control` | 12 | 22 | Arrival order | technology | SATISFIED | stale-context |
| `reordered-arrival` | 32 | 22 | Arrival order | travel | VIOLATED | stale-context |
| `event-time-reconciliation` | 32 | 22 | Event time | technology | SATISFIED | stale-context |
| `late-arrival` | 12 | 45 | Event time | travel | VIOLATED | delayed-events |

The reordered pair has identical delivery history across policies. Arrival-order
processing overwrites newer state with the older event. Event-time processing
retains the event with the latest occurrence timestamp. Both paths process only
arrivals at or before the decision boundary.

In the late case, b exists in harness history but is unavailable to the system
at second 40. Reconciliation can only select a. Evidence records b's subsequent
arrival at 45 to explain the missing state; that future arrival is never supplied
to the decision path. The harness's knowledge of b defines expected state.

The canonical class distinguishes unavailable latest state (`delayed-events`)
from an older selected state despite timely availability (`stale-context`).
Satisfied cases retain the class of the invariant being tested. All four
`detected` observations are null. Successful reconciliation is mitigation
behavior and emits no detection signal.

## Evidence and Verification

Event-time provenance schema version 1 records each event's identity, value,
occurrence timestamp, and ingestion timestamp; the decision timestamp; selection
policy; expected/observed event and value; evaluation; source/runtime metadata;
and nullable detection. Deliveries are listed in ingestion order.

`EventTimeInvariant` independently selects the latest logical event at or before
the decision. Missing eligible history yields NOT_APPLICABLE. Duplicate event
IDs, ambiguous occurrence-time ties, ingestion before occurrence, and observations
that had not arrived at the boundary are invalid evidence. This fixture assumes
one ordered logical history and consistent clocks.

The Python verifier separately recomputes logical eligibility, arrival
availability, policy selection, outcome, taxonomy, and invariant status from
the recorded clocks. CI executes the four cases, verifies the resulting JSONL,
and retains `event-time-ordering-SHA` artifacts for 30 days.

## Scope

These are fixed, single-key experiments in memory. They do not model watermarks,
bounded lateness, clock skew, multiple partitions, durable state, concurrent
consumers, or retroactive repair after a published decision. Equal event times
need an explicit tie rule before the model can be extended. Reconciliation here
means selecting the newest event already available at the boundary.

The five-case released preview pack and the separate duplicate-replay command
retain their existing formats. Run this scenario and its verifier separately.
