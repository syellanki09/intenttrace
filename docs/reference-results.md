# Implemented Reference Experiments

IntentTrace currently executes four synthetic experiment families with 12 cases.
This page describes expected outcomes for the implemented fixtures. Actual runs
record their full source SHA and environment. The published `v0.1.0-preview.1`
contains only the five context and contract cases; replay and event-time cases
were added afterward. No new release is established by this page.

Run all families from a clean checkout with JDK 17 and Python 3.9+:

```bash
python3 tools/run_suite.py
python3 tools/verify_suite.py /path/to/generated/suite.zip
```

The [suite guide](scenario-suite.md) describes the manifest, raw evidence,
checksums, record counts, and offline archive verification.

| Family | Control | Injected behavior | Comparison or mitigation | Independent verifier |
| --- | --- | --- | --- | --- |
| stale-context | Latest eligible version: technology, SATISFIED | Older pinned version: travel, VIOLATED | Same immutable history and decision boundary | `verify_results.py` |
| contract-unit-drift | Coordinated unit upgrade: 2000 ms, SATISFIED | Unit drift across versions or under the same version: 2000000 ms, VIOLATED | Cross-client outcomes for the same logical duration | `verify_contract_results.py` |
| duplicate-replay | Unique deliveries: 8 points, SATISFIED | Repeated contribution: 11 points, VIOLATED | Deduplicate event identity: 8 points, SATISFIED | `verify_replay_results.py` |
| event-time-ordering | Ordered delivery: technology, SATISFIED | Older arrival overwrites state, or latest event arrives too late: travel, VIOLATED | Event-time selection repairs reordered arrivals; late state remains unavailable | `verify_event_time_results.py` |

## Stale Context

**Invariant:** select the latest context committed at or before the decision.
The fixed setup commits version 1 with travel, then version 2 with technology.
The control resolves version 2. Injection pins version 1 while preserving the
same store, latest eligible version, and boundary. Both decisions complete;
only the injected selection violates freshness. Provenance records used and
latest eligible snapshots and evaluation independently of system detection.

```bash
./gradlew :benchmarks:run --no-daemon
python3 tools/verify_results.py benchmarks/build/results/stale-context/results.jsonl
```

**Limit:** a synthetic versioned store and deterministic pinned read, without a
production cache or replica. See [stale-context reproduction](reproduction.md).

## Duration Contract Drift

**Invariant:** producer and consumer interpretation agree for one logical input.
The fixed input is 2000 milliseconds. A reference web client reads milliseconds.
A coordinated seconds-based producer/consumer upgrade agrees with the reference.
Sending milliseconds to a seconds-based consumer produces 2000000 milliseconds;
the fixture demonstrates both a version upgrade mismatch and drift under the
same contract version. Wire JSON, client versions, unit assumptions, and outcomes
allow the independent verifier to recompute the interpretation.

```bash
./gradlew :benchmarks:runContractScenario --no-daemon
python3 tools/verify_contract_results.py benchmarks/build/results/contract-unit-drift/results.jsonl
```

**Limit:** one integer-duration contract and fixed input; it does not establish
general SDK compatibility. See [contract compatibility](contract-compatibility.md).

## Duplicate Replay

**Invariant:** each logical event contributes once regardless of delivery count.
Two events contribute 3 and 5 points. The control totals 8; injection repeats the
first event and naive processing totals 11. In-memory deduplication by event ID
preserves 8 for that same replayed sequence. Ordered delivery IDs, payloads, and
application markers explain each contribution, and independent evaluation checks
both the total and per-identity application count.

```bash
./gradlew :benchmarks:runReplayScenario --no-daemon
python3 tools/verify_replay_results.py benchmarks/build/results/duplicate-replay/results.jsonl
```

**Limit:** in-memory identity tracking, without restart, concurrency, retention,
or durable exactly-once guarantees. See [duplicate replay](duplicate-replay.md).

## Event-Time Ordering and Late Arrival

**Invariant:** the decision reflects the latest logical event generated by its
boundary. Event a sets travel at second 10; event b sets technology at 20; the
decision occurs at 40. Ordered arrivals at 12 and 22 yield technology. Delaying a
to 32 makes arrival-order processing overwrite that state with travel. Selecting
the latest event by occurrence time restores technology for the same arrivals.
If b arrives at 45, event-time processing still yields travel at the boundary.

The evidence keeps occurrence, ingestion, and decision clocks distinct. Reordered
selection is classified as `stale-context`; unavailable latest state is classified
as `delayed-events`. The verifier recomputes availability and selection from those
clocks rather than trusting the status field.

```bash
./gradlew :benchmarks:runEventTimeScenario --no-daemon
python3 tools/verify_event_time_results.py benchmarks/build/results/event-time-ordering/results.jsonl
```

**Limit:** a single key, consistent clocks, and distinct event times. Watermarks,
durable state, clock skew, and repair of published decisions are not modeled.
See [event-time ordering](event-time-ordering.md).

## Interpretation

Ground-truth violation, diagnostic provenance, and system detection observations
remain separate. All 12 fixture records have `detected = null`: no independent
system detector is implemented. A successful comparison or mitigation is not a
detection signal. These experiments establish reproducible synthetic mechanisms;
they do not establish production prevalence, business impact, adoption, external
reproduction, or a reliability improvement percentage. Missing-context and
conflicting-values experiments remain planned.
