# IntentTrace 0.1.0-preview.2 - Draft Release Notes

Status: unpublished review material. No release date or final release commit is
assigned. The existing release remains `v0.1.0-preview.1`; Gradle and citation
metadata still describe that release. Remove this draft notice only after the
maintainer approves the final metadata, source, evidence, and publication.

## Changes Since Preview 1

- Four executable experiment families and 12 cases, compared with five context
  and contract cases in preview 1.
- Duplicate replay compares unique delivery, repeated application, and in-memory
  deduplication by event identity.
- Event-time ordering compares ordered arrivals, an older event arriving last,
  event-time reconciliation, and a newer event arriving after the decision.
- One complete-suite command runs the tests and demonstrations, independently
  verifies their results, and produces a combined evidence archive.
- A manifest indexes all four raw JSONL files with full source identity, hashes,
  record counts, canonical scenario/failure IDs, and verification status.
- Deterministic ZIP metadata, live failure diagnostics, offline verification,
  consolidated reference results, and complete-suite artifacts in ordinary and
  cold-cache CI improve the reproduction workflow.

## Proposed Attachments

- `suite.zip`: the verified complete archive from the final release source.
- `manifest.json`: the raw-evidence index, separately accessible.
- `suite-report.json`: per-case summaries and evidence hashes.
- `SHA256SUMS`: generated hashes for those exact three attachment files.

Every attachment must come from the same successful final-source execution.
The [candidate checklist](preview-2-review.md) documents the
`tools/prepare_release_assets.py` command that verifies the source and prepares
these four files without publication.
The suite ZIP includes all four raw JSONL files, the compatible nested preview
ZIP, and README. A full suite run also includes its build log; package-only CI
archives can omit that log. GitHub source archives are separate source downloads.
Checksums establish consistency, not authorship or authenticity.

Readers can verify a downloaded suite with Python alone:

```bash
python3 tools/verify_suite.py /path/to/suite.zip
```

## Compatibility and Scope

The software preview version is separate from data-format versions: raw-evidence
manifest schema 1, suite report 2, and the existing scenario-specific schemas.
The current suite verifier also reads suite report 1. Older suite verifiers do
not read the new indexed format; use the verifier from the tested source.
The original preview commands and published preview-1 artifacts remain usable.

The fixtures are synthetic, fixed-input experiments. Missing/conflicting-value
benchmarks, durable deduplication, concurrent processing, clock-skew handling,
watermarks, retroactive decision repair, and production integrations remain
future work. APIs and schemas remain experimental. Runtime metadata and logs may
vary between reproductions.

No production prevalence, business impact, reliability percentage, adoption,
independent human reproduction, DOI, or archival deposit is established by this
draft. See [reference results](../reference-results.md) for the implemented scope
and [contributor guidance](../../CONTRIBUTING.md) for reproduction feedback.
